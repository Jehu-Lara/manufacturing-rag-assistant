# CLAUDE.md — Manufacturing Knowledge RAG Assistant

Project-specific instructions for Claude Code sessions working in this repo. Read this AND `SPEC.md` before changing anything, and run `pytest` before starting work to confirm the baseline is green.

This repo went through a `src/` modular-monolith refactor (see `docs/architecture/MIGRATION_PLAN.md` if present, and `docs/adr/001-modular-monolith-src-layout.md` onward) — the old flat `api/`/`ingestion/`/`retrieval/`/`eval/`/`ui/` packages no longer exist except as data/build-artifact directories (`ingestion/output/`, `retrieval/output/`, `eval/eval_set.json`, `eval/reports/`). All application code lives under `src/`.

## How to start a session in this repo

1. Read `SPEC.md` in full (scope, acceptance criteria, no-goals, data-honesty and language policy, phase status).
2. Read this file in full.
3. Run `pytest` and confirm all tests pass before making changes. If they don't, that's the first thing to fix — don't build on a red baseline.
4. Before adding or changing anything under `corpus/`, read `corpus/SOURCES.md` — every corpus file must have a matching row there.

## Tech Stack

- Python 3.11 (production/CI target; `pyproject.toml`'s own `requires-python` is left open-ended since local dev environments may run newer Python — see `docs/adr/001-modular-monolith-src-layout.md`)
- `pyyaml` — frontmatter parsing
- `tiktoken` (cl100k_base) — token counting for chunk sizing (NOT the embedding model's tokenizer — see the Language Policy note in `SPEC.md`)
- `pytest` — tests
- `sentence-transformers`, `chromadb`, `rank-bm25`, `numpy` — embeddings, vector store, BM25 lexical index, hybrid retrieval
- `fastapi`, `uvicorn[standard]`, `streamlit`, `groq`, `openai`, `pydantic`, `httpx`, `python-dotenv`, `opentelemetry-api` — generation API, UI, LLM clients, config/env loading, tracing

## Commands

- `python -m src.features.ingestion.cli` — run the ingestion pipeline over the full corpus; prints document count, chunk count, public/synthetic breakdown, and total corpus size; writes `ingestion/output/chunks.jsonl` (gitignored, regenerated on every run; the `ingestion/` directory itself still exists purely as this build-artifact location).
- `python -m src.features.retrieval.cli` — embeds all chunks (`BAAI/bge-m3`) and builds the ChromaDB vector store + BM25 JSON lexical index under `retrieval/output/` (gitignored, regenerated on every run); requires `ingestion/output/chunks.jsonl` to already exist.
- `python -m src.features.evaluation.retrieval_eval` — runs the hand-written eval set through the hybrid retriever, writes a versioned recall@k/MRR report to `eval/reports/`.
- `python -m src.features.evaluation.threshold_analysis` — sweeps the refusal cosine-similarity threshold against the eval set to find the answerable/unanswerable separation point.
- `python -m src.features.evaluation.generation_eval` — runs the eval set end-to-end through retrieval + generation, checking citation correctness and refusal behavior.
- `python -m src.features.evaluation.eval_set_integrity --verify` / `--write` — verify or regenerate `eval/eval_set.json`'s stored SHA-256 hash (the file itself stays at `eval/eval_set.json`, never packaged under `src/` — it's data, not code).
- `uvicorn src.main:app --reload` — run the FastAPI backend locally (serves `GET /health`, `GET /ready`, `POST /query`).
- `streamlit run src/web/app.py` — run the UI locally; expects the backend already running, reads the `API_BASE_URL` env var (default `http://localhost:8000`).
- `docker build -t rag4 .` / `docker run -p 7860:7860 rag4` — combined-container deploy build/run (FastAPI + Streamlit + nginx in one image; this shape is a carried-over default from an abandoned HF-Spaces target, not something the actual current deploy target requires — see `docs/adr/005-deploy-container-shape.md`). Verified end-to-end on amd64 (real `docker build`/`docker run`, `/health` and `/ready` both correctly proxied through nginx, `index_loaded: true` against the real baked-in index). **The actual deploy target is Oracle Cloud's Always Free Ampere A1 (ARM) VM** (`SPEC.md`'s Phase 3 status — HF Spaces was dropped 2026-08-25, no free tier can run a Docker SDK Space anymore), currently blocked on Oracle's own regional ARM capacity limit, not a code issue; native ARM verification (only QEMU-emulated so far) remains pending until a VM is actually provisionable.
- `pytest` — run all tests.
- `ruff check src tests` / `mypy src` — lint and type-check (config in `pyproject.toml`; `mypy` runs `--strict` with a bare top-level `strict = true` — no per-module carve-outs — plus two narrowly scoped `ignore_missing_imports` overrides for `rank_bm25`/`yaml`, which ship no stubs; `python_version = "3.12"` is a permanent, documented mypy-only exception, not a workaround pending removal — see `docs/adr/001-modular-monolith-src-layout.md`). `.github/workflows/ci.yml` runs both, plus the eval-set hash check and the full test suite, on every push/PR to `master`.

## Conventions

- Python: `snake_case` for modules, functions, and variables; `PascalCase` for classes/dataclasses.
- One dataclass per concept in `src/domain/models.py` — don't scatter metadata field definitions across multiple files. `ChunkMetadata`, `RetrievalResult`, `Citation`, and `QueryAnswer` all live there; they're the framework-free domain types every layer converts to/from.
- Type hints are required on all function signatures.
- Docstrings: one line, only where the behavior is genuinely non-obvious (a hidden constraint, a subtle invariant, a workaround). Do not write docstrings that just restate the function name in prose. Prefer none over a redundant one.
- No inline comments explaining *what* code does — the code should read clearly enough that it doesn't need one. A comment is justified only for *why*, when the why isn't obvious from context.
- **Modular monolith with ports/adapters**: `src/domain/` (models, policies, ports) has zero imports of fastapi/chromadb/groq/openai/streamlit/torch — enforced by `tests/test_import_invariants.py` (static AST parsing, not a runtime check). `src/domain/ports.py` defines five `Protocol`s (`RetrieverPort`, `LLMClientPort`, `VectorStorePort`, `EmbedderPort`, `LexicalIndexPort`); concrete implementations live under `src/adapters/secondary/`. `src/features/*/use_cases.py` orchestrate ports; `src/adapters/primary/http/` + `src/features/query/router.py` are the only places FastAPI is imported outside `src/main.py`.
- **Mocking convention**: real LLM API calls are the one thing in this repo deliberately kept out of tests, for cost and determinism. `tests/test_llm_adapter.py` patches the provider SDK clients (`groq_openai_client.groq.AsyncGroq`, `groq_openai_client.openai.AsyncOpenAI`) directly with `unittest.mock.AsyncMock`; higher-layer tests use **port fakes** (`tests/fakes.py`'s `InMemoryLLMClient`/`InMemoryRetriever`/`InMemoryVectorStore`, or scripted per-question fakes like `tests/test_evaluation_generation_eval.py`'s), injected via constructor args or FastAPI's `app.dependency_overrides` — not module-level patching of `answer_question`/`retrieve` the way the pre-refactor code did. This is a scoped exception (SDK boundary), not a new general testing policy — ingestion, retrieval, and eval-metrics tests are all real integration tests against real models/indexes, deliberately.
- **Config/env-loading pattern**: `src/core/config.py`'s `Settings` is a plain, frozen **pydantic `BaseModel`** (deliberately NOT `pydantic_settings.BaseSettings` — verified directly that `BaseSettings` lets an ambient env var override a field's coded default even on direct construction, which would silently contaminate the many tests that construct `Settings(...)` without passing every field). `load_settings()` is the one place environment variables are read. `.env` (gitignored) is loaded via `python-dotenv` only if present — never required, because deployment credentials are supplied as runtime environment variables on the Oracle VM/container. Config-typo values (e.g. an invalid `LLM_PROVIDER`, a non-float `REFUSAL_COSINE_THRESHOLD`) raise `ValueError` at load time; genuinely-optional values (missing API keys) default to `None` without raising and are only checked when actually needed. `chroma_path`/`bm25_path` default to `retrieval/output/chroma` / `retrieval/output/bm25_index.json` (overridable via `CHROMA_PATH`/`BM25_PATH`) — the same physical locations the pre-refactor code used, so a built index keeps working across the move.
- **Structured logging**: `src/core/logging.py`'s `JsonFormatter` + `configure(level)` writes one JSON object per log line to stdout for capture by the container runtime; any caller-supplied `extra={...}` fields are passed through generically, and the active OpenTelemetry span's trace id (if any) is included as `trace_id` (see `docs/adr/006-observability.md`). There is no external log aggregation — this is intentionally simple, appropriate for a portfolio-scale app, not a production system. Don't over-engineer this later.
- **Citation-integrity design (hard rule)**: citations in API responses are always re-derived from real retrieved-chunk metadata by `chunk_id`, never trusted from LLM-generated citation fields beyond the `chunk_id` itself — see the Prohibited Patterns entry below. `src/domain/policies.py`'s `CitationResolver.resolve` looks up `document_id`, `document_title`, `section_heading`, and `revision` from the retrieved chunk matching the LLM-supplied `chunk_id`, dropping (logging, not raising) any citation whose `chunk_id` isn't among the retrieved set.
- **Byte-stable invariants** (never change without an explicit, deliberate decision): refusal cosine threshold `0.5999` (`src/core/config.py`), RRF `k=60` with ties broken by ascending `chunk_id` (`src/domain/policies.py`). Both are directly unit-tested in `tests/test_domain_policies.py` and `tests/test_core_config.py`.
- **LLM/generation module boundary**: `src/adapters` + `src/features` (FastAPI backend + LLM orchestration) and `src/web` (Streamlit) are separate processes communicating over HTTP only. `src/web/` must never import from `src.domain`, `src.features`, or `src.adapters` directly, even though both live in the same container/repo — this matches the deployed architecture (nginx proxies to two independent processes) and keeps the API genuinely independently testable and reachable. `src/web/i18n.py`'s `UI_LABELS` is a deliberate exception to "don't duplicate": it's a small, documented data duplication of the same catalog concept as `src/features/query/prompts.py`'s `REFUSAL_MESSAGE`/`GENERATION_ERROR_MESSAGE`, kept separate specifically so `src/web/` never needs to import `src.features`.
- Folder layout: `corpus/{public,synthetic}/`, `tests/` (+ `tests/fixtures/mini_corpus/` — a tiny 2-document fixture corpus for CI-safe ingestion/retrieval CLI smoke tests, not the real corpus), `src/core/` (config, errors, logging, telemetry), `src/domain/` (models, policies, ports — framework-free), `src/features/{ingestion,query,retrieval,evaluation}/`, `src/adapters/{primary/http, secondary/{embedder,vector,lexical,llm}}/`, `src/web/` (Streamlit), `src/main.py` (composition root — deliberately lightweight, all adapter construction happens inside FastAPI's `lifespan`, never at import time), `docs/adr/` (6 ADRs), `docs/architecture/` (C4 mermaid diagrams). `ingestion/output/`, `retrieval/output/`, `eval/eval_set.json`, `eval/reports/` remain as data/build-artifact directories, not code. Don't invent new top-level folders without a reason tied to a specific phase's scope.

## CFR Numbering → Markdown Heading Convention

Federal regulation text (21 CFR Part 211, 29 CFR 1910.1200) is numbered (`§ 211.22`, paragraph `(a)`, sub-paragraph `(1)`), not naturally headed the way an SOP or manual is. When converting CFR text to the corpus Markdown format, each numbered level maps one-to-one to a Markdown heading level:

- `##` — a Subpart (e.g. `## Subpart B—Organization and Personnel`) or, where a section stands with its own numbered paragraphs, the section itself (e.g. `## (a) Purpose`).
- `###` — an individual section (`### § 211.22 Responsibilities of quality control unit`) or a lettered paragraph under a section-level `##`.
- `####` — a numbered sub-paragraph, if it's substantial enough to need its own heading (short numbered items are usually left as plain list items within their parent heading instead — use judgment; the goal is a `section_heading` breadcrumb from the chunker that's still a useful citation, not a heading for every single `(a)(1)(i)`).

Apply this convention consistently if more regulatory text is added to the corpus later — don't invent a different scheme per document.

## Prohibited Patterns

- **No hardcoded API keys.** `.env.example` is tracked with empty placeholder keys; the real `.env` is gitignored.
- **No chunk emitted with incomplete metadata.** Every chunk must have a non-empty `document_id`, `document_title`, `section_heading`, `source_type`, `source_url_or_note`, `chunk_id`, and `md_line_range`. `source_page_range` is the one documented exception — `null` is valid and expected for every synthetic document (see `src/domain/models.py`'s `ChunkMetadata`). If a required field would be empty, the pipeline must raise, not silently drop or default it — this mirrors the citation-mandatory, no-silent-fallback-to-hallucination standard the whole project is built around.
- **No copyrighted PDFs committed to this repo**, ever. See `SPEC.md`'s Data-Honesty Policy.
- **No new corpus file without a matching `corpus/SOURCES.md` row.** `tests/test_ingestion_use_cases.py` enforces this — don't skip it or mark it `xfail` to get a file in.
- **No silent fallback that could look like hallucination-adjacent behavior** — don't build patterns (e.g. defaulting a missing field to `"unknown"` instead of raising) that could mask a real gap.
- **No citation field trusted from LLM output beyond `chunk_id`.** `src/domain/policies.py`'s `CitationResolver` always looks up `document_id`/`document_title`/`section_heading`/`revision` from the real retrieved chunk's metadata, never from the LLM's own JSON output — this is what prevents citation hallucination; a change that starts trusting LLM-supplied citation text for these fields would reintroduce exactly the failure mode this project is built to avoid.
- **No `pickle.load`/`pickle.dump` in this project's own runtime code.** `src/adapters/secondary/lexical/bm25_lexical_index.py` persists the BM25 index as JSON (tokenized corpus, rebuilt in memory on load) specifically to avoid this — see `docs/adr/004-bm25-json-persistence.md`.
- **No new module-level mutable singleton** (the pre-refactor code's `_model`/`_CACHE`/`_encoding` globals were eliminated during the `src/` migration — don't reintroduce the pattern; adapter/composition-root-managed instance state is the replacement).
