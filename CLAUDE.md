# CLAUDE.md — Manufacturing Knowledge RAG Assistant

Project-specific instructions for Claude Code sessions working in this repo. Read this AND `SPEC.md` before changing anything, and run `pytest` before starting work to confirm the baseline is green.

This repo went through a `src/` modular-monolith refactor (see `docs/architecture/MIGRATION_PLAN.md` if present, and `docs/adr/001-modular-monolith-src-layout.md` onward) — the old flat `api/`/`ingestion/`/`retrieval/`/`eval/`/`ui/` packages no longer exist except as data/build-artifact directories (`ingestion/output/`, `retrieval/output/`, `eval/eval_set.json`, `eval/reports/`). All application code lives under `src/`.

**This repository is public on GitHub** (made public 2026-08-28, after a full-history audit for secrets/API keys/PII found nothing — `.env` was never committed at any point in history, `.env.example` only ever had empty placeholders). Treat every future commit as world-readable: never stage `.env`, a real API key, or a copyrighted source PDF, and never rewrite/force-push history to "fix" a leak after the fact — flag it and rotate the credential instead.

## How to start a session in this repo

1. Read `SPEC.md` in full (scope, acceptance criteria, no-goals, data-honesty and language policy, phase status).
2. Read this file in full.
3. Run `pytest` and confirm all tests pass before making changes. If they don't, that's the first thing to fix — don't build on a red baseline.
4. Before adding or changing anything under `corpus/`, read `corpus/SOURCES.md` — every corpus file must have a matching row there.

## Commands

- `python -m src.features.ingestion.cli` — run the ingestion pipeline over the full corpus; prints document count, chunk count, public/synthetic breakdown, and total corpus size; writes `ingestion/output/chunks.jsonl` (gitignored, regenerated on every run; the `ingestion/` directory itself still exists purely as this build-artifact location).
- `python -m src.features.retrieval.cli` — embeds all chunks (`BAAI/bge-m3`) and builds the ChromaDB vector store + BM25 JSON lexical index under `retrieval/output/` (gitignored, regenerated on every run); requires `ingestion/output/chunks.jsonl` to already exist. Also writes `retrieval/output/index_manifest.json` (profile + deterministic `chunks_sha256`/`corpus_sha256` + build commit). The `INDEX_PROFILE` env var picks the embedding profile: `contextual-v1` (**default**, shipped 2026-08-30 — embeds `document_title > section_heading\n\nchunk_text`, stores the raw `chunk_text` unchanged in `documents=`/metadata; ADR-008) or `raw-v1` (embeds the bare body — the tested rollback path). It **is** a `Settings` field (`index_profile`), read and validated in `load_settings()` like every other env var, and a bad value raises `ValueError` at load time. It stays env-overridable precisely because `raw-v1` is the documented rollback path — unlike `expansion_mode`, which is deliberately NOT a `Settings` field so production stays hard-wired to `"off"`. The eval runners call `_eval_retriever.assert_live_index_profile(...)` and refuse to measure a live index whose manifest profile doesn't match the report label.
- `python -m src.features.evaluation.retrieval_eval` — runs the hand-written eval set through the hybrid retriever, writes a versioned recall@k/MRR report to `eval/reports/`.
- `python -m src.features.evaluation.threshold_analysis` — sweeps the refusal cosine-similarity threshold against the eval set to find the answerable/unanswerable separation point.
- `python -m src.features.evaluation.generation_eval` — runs the eval set end-to-end through retrieval + generation, checking citation correctness and refusal behavior.
- `python -m src.features.evaluation.eval_set_integrity --verify` / `--write` — verify or regenerate `eval/eval_set.json`'s stored SHA-256 hash (the file itself stays at `eval/eval_set.json`, never packaged under `src/` — it's data, not code).
- `python -m src.features.evaluation.regression_eval` — runs the frozen bilingual regression query set (`eval/regression_queries.json`) through the retriever in each `expansion_mode`, writing `eval/reports/regression_eval_v<version>.md`.
- The four eval runners above (`retrieval_eval`, `threshold_analysis`, `generation_eval`, `regression_eval`) measure the **live** index and default their report label to `index_profile="raw-v1"`. Since `contextual-v1` is now the built default, a bare invocation raises `RuntimeError` from the `assert_live_index_profile` guard — pass `index_profile="contextual-v1"` (matching the live manifest) or rebuild the rollback index with `INDEX_PROFILE=raw-v1 python -m src.features.retrieval.cli` first.
- `python -m src.features.evaluation.regression_set_integrity --verify` / `--write` — SHA-256 freeze guard for `eval/regression_queries.json` (mirrors `eval_set_integrity`; hash is over the parsed `queries`, not raw bytes).
- `python -m src.features.evaluation.gate_holdout_integrity --verify` / `--write` — freeze + composition guard for `eval/gate_holdout_v1.0.0.json` (Phase 3, ADR-009). `--verify` enforces `status == "frozen"`, 48 questions / 24 EN-ES pairs (`pair_id`), 24/24 by class and language, per-class fields, `expected_chunk_ids` ⊆ `chunks.jsonl`, EN/ES answerable pair halves targeting the **same** `expected_chunk_ids`, no normalized-text collision with `eval_set`/`regression_queries` (**both mandatory and themselves integrity-verified first**), and no two holdout questions identical after NFKC+casefold+whitespace. `--write` is atomic (tmp+replace) and only re-stamps the hash — it never authors questions. **The 48 questions were content-approved by the owner and the file was frozen (`status: frozen`) on 2026-09-01, so CI's `gate_holdout` step is green;** it was red by design while the holdout was an unfrozen draft.
- `python -m src.features.evaluation.gate_score_guard` — CI guard (after the index build): fails if `r001`/`r002` top1-semantic leave `[0.5500, 0.5999)` on the freshly built index. Checks the band, never an exact cosine.
- `python -m src.features.evaluation.gate_holdout_profile` — **owner pre-freeze check** (Phase 3C). Buckets all 48 holdout questions by gate band on `contextual-v1/off`; exits non-zero unless every EN/ES × answerable/unanswerable cell has ≥3 questions in the grounded-review band. A failure means author another draft with more borderline questions — never lower the floor. Writes `eval/reports/gate_holdout_band_profile.{md,json}`. Needs a 48-question holdout (draft is fine) and a coherent live index.
- `python -m src.features.evaluation.floor_sweep` — sweeps candidate review floors (`[0.50, ..., 0.55]`) and four signal combinations (`none`, `sem_top1_in_bm25_top_n`, `sem_bm25_top1_agree`, `channels_overlap_top_n`) across the evaluation set and regression queries. Assesses rules against global gates G1–G4 and writes timestamped calibration runs under `eval/calibration/` with `features.jsonl`, `grid.json`, `report.md`, and `sanitized_summary.md` (summary committed at `docs/eval/floor_sweep_summary.md`).
- `python -m src.features.evaluation.gate_generation_eval --provider {groq|openai}` — **owner paid run** (Phase 3C). Verifies the three frozen datasets + live `contextual-v1` index + that `--provider` matches `LLM_PROVIDER`, enforces the grey-band coverage check (≥3 per cell) on the snapshot, then retrieves each holdout question once and replays the identical results through a `binary` and a `grounded_review` `QueryUseCase`. Holdout ×3 + `r001/r002/r018-r020` canary ×3; the confident-band LLM call is byte-identical between policies so it is shared **within** a repeat, never across. Provider fallback forced off; every physical provider round trip (incl. 429s, schema fallbacks, network failures) is counted, and reported latency is per physical LLM call + a separate live-retrieval p50/p95, never question wall-clock. Gates include `no_rate_limiting`, `repeats_conform` (verifies full holdout ×3 and canary ×3 repeats match preregistration; fails on single-repeat exploratory pilots), and canary answers that must **cite the expected chunk**. Writes a **write-once, atomic** `eval/reports/gate_generation_eval_<UTC>/` (built in `<id>.partial/` then renamed) with `run_manifest.json`, `retrieval.jsonl`, `outcomes.jsonl`, `comparison.md`, `blind_checklist.csv` (opaque `arm-A`/`arm-B`, one row per attempt, answer + evidence + expected, includes any unanswerable that was answered), `blind_checklist.baseline.json` (sealed immutable half), `arm_map.sealed.json`, `checksums.txt`; logs `error_type`/status only. After grading the checklist by hand: `python -m src.features.evaluation.gate_generation_eval --import-verdicts <run_dir>` (no `--provider` needed) re-scores the citation/faithfulness + safe gates and writes `import_manifest.json`, `comparison.import.md`, and `checksums.import.txt` as separate artifacts, without mutating any sealed file (`run_manifest.json`, `comparison.md`, and `checksums.txt` stay byte-identical, so the run re-verifies identically afterwards). Imports are single-use: a second run fail-closes on the existing `checksums.import.txt`. It first verifies immutable files (`run_manifest.json`, `outcomes.jsonl`, `retrieval.jsonl`, `blind_checklist.baseline.json`, `arm_map.sealed.json`) against `checksums.txt` to fail-close on tampering, checks the graded CSV against the sealed baseline (exact row set, no dupes, immutable columns unchanged; only the pass/notes columns editable), and cross-checks the answered-unanswerable count against `outcomes.jsonl`, so a deleted "unsafe" row can't make a gate pass falsely. Automated gates are advisory — the ship decision, ADR-009→Accepted and the default flip are the owner's. **Not wired into CI.**

## Conventions

- Python: `snake_case` for modules, functions, and variables; `PascalCase` for classes/dataclasses.
- One dataclass per concept in `src/domain/models.py` — don't scatter metadata field definitions across multiple files. `ChunkMetadata`, `RetrievalResult`, `Citation`, and `QueryAnswer` all live there; they're the framework-free domain types every layer converts to/from.
- Type hints are required on all function signatures.
- Docstrings: one line, only where the behavior is genuinely non-obvious (a hidden constraint, a subtle invariant, a workaround). Do not write docstrings that just restate the function name in prose. Prefer none over a redundant one.
- No inline comments explaining *what* code does — the code should read clearly enough that it doesn't need one. A comment is justified only for *why*, when the why isn't obvious from context.
- **Modular monolith with ports/adapters**: `src/domain/` (models, policies, ports) has zero imports of fastapi/chromadb/groq/openai/streamlit/torch — enforced by `tests/test_import_invariants.py` (static AST parsing, not a runtime check). `src/domain/ports.py` defines five `Protocol`s (`RetrieverPort`, `LLMClientPort`, `VectorStorePort`, `EmbedderPort`, `LexicalIndexPort`); concrete implementations live under `src/adapters/secondary/`. `src/features/*/use_cases.py` orchestrate ports; `src/adapters/primary/http/` (which owns the routes, in `routes.py`) is the only place FastAPI is imported outside `src/main.py` — `src/features/` is framework-free and must never import `fastapi` or `src.adapters.primary`, enforced by `tests/test_import_invariants.py`.
- **Mocking convention**: real LLM API calls are the one thing in this repo deliberately kept out of tests, for cost and determinism. `tests/test_llm_adapter.py` patches the provider SDK clients (`groq_openai_client.groq.AsyncGroq`, `groq_openai_client.openai.AsyncOpenAI`) directly with `unittest.mock.AsyncMock`; higher-layer tests use **port fakes** (`tests/fakes.py`'s `InMemoryLLMClient`/`InMemoryRetriever`/`InMemoryVectorStore`, or scripted per-question fakes like `tests/test_evaluation_generation_eval.py`'s), injected via constructor args or FastAPI's `app.dependency_overrides` — not module-level patching of `answer_question`/`retrieve` the way the pre-refactor code did. This is a scoped exception (SDK boundary), not a new general testing policy — ingestion, retrieval, and eval-metrics tests are all real integration tests against real models/indexes, deliberately.
- **Config/env-loading pattern**: `src/core/config.py`'s `Settings` is a plain, frozen **pydantic `BaseModel`** (deliberately NOT `pydantic_settings.BaseSettings` — verified directly that `BaseSettings` lets an ambient env var override a field's coded default even on direct construction, which would silently contaminate the many tests that construct `Settings(...)` without passing every field). `load_settings()` is the one place environment variables are read. `.env` (gitignored) is loaded via `python-dotenv` only if present — never required, because deployment credentials are supplied through Hugging Face runtime secrets. Never declare them as Docker build arguments. Config-typo values (e.g. an invalid `LLM_PROVIDER`, a non-float `REFUSAL_COSINE_THRESHOLD`) raise `ValueError` at load time; genuinely-optional values (missing API keys) default to `None` without raising and are only checked when actually needed. `chroma_path`/`bm25_path` default to `retrieval/output/chroma` / `retrieval/output/bm25_index.json` (overridable via `CHROMA_PATH`/`BM25_PATH`). `load_settings()` also owns `INDEX_PROFILE`, `DEPLOYED_SHA` and `OTEL_EXPORTER_OTLP_ENDPOINT`, and rejects a non-positive `RATE_LIMIT_PER_MINUTE` (a limiter with `max_requests <= 0` would boot healthy and 429 everyone). `src/core/paths.py` is the single repo-root authority — it imports nothing but `pathlib`, so even the dependency-light integrity guards can bind their paths from it; no module computes its own `Path(__file__).resolve().parent...` chain, enforced by `tests/test_core_paths.py`.
- **Structured logging**: `src/core/logging.py`'s `JsonFormatter` + `configure(level)` writes one JSON object per log line to stdout for capture by the container runtime; any caller-supplied `extra={...}` fields are passed through generically, and the active OpenTelemetry span's trace id (if any) is included as `trace_id` (see `docs/adr/006-observability.md`). There is no external log aggregation — this is intentionally simple, appropriate for a portfolio-scale app, not a production system. Don't over-engineer this later.
- **Citation-integrity design (hard rule)**: citations in API responses are always re-derived from real retrieved-chunk metadata by `chunk_id`, never trusted from LLM-generated citation fields beyond the `chunk_id` itself — see the Prohibited Patterns entry below. `src/domain/policies.py`'s `CitationResolver.resolve` looks up `document_id`, `document_title`, `section_heading`, `revision`, and `source_type` from the retrieved chunk matching the LLM-supplied `chunk_id`. It is **fail-closed**, like `GroundedEvidenceResolver`: one citation naming a chunk that wasn't retrieved, one malformed entry, or one retrieved chunk whose metadata is missing a citation field rejects the **whole set** and returns `CitationResolution([], "unresolved_citation")`, which `QueryUseCase` degrades to the canonical refusal. It never raises and never logs citation content. Partial resolution (dropping the bad entry, serving the rest) is the behaviour this replaced — it presented a partly-unverifiable answer as fully cited.
- **`source_type` reaches the reader.** `Citation` carries `source_type` (`public` | `synthetic`) through the domain model, the HTTP body, and the UI; `src/web/render.py` badges **only** synthetic sources (`UI_LABELS[lang]["synthetic_source_badge"]`). An unbadged line is a positive claim that the source is a real public document, so never badge everything and never badge a public source. Every answered response also renders `UI_LABELS[lang]["safety_notice"]`; refusals and technical errors deliberately do not, since they carry no generated content to verify.
- **Prompt data envelope**: `build_user_prompt` serializes the question and the retrieved corpus as JSON inside `<retrieved_context_json>` … `</retrieved_context_json>`. The chunk text is passed through **unaltered** — `json.loads()` on the envelope must return the exact bytes the retriever produced, because `GroundedEvidenceResolver` validates verbatim quotes against that raw text. `tests/test_prompt_injection_canary.py` holds the EN/ES canary; read its module docstring before claiming anything about prompt-injection resistance — a unit test proves the envelope and the fail-closed gates, not model behaviour.
- **Query acronym expansion (retrieval-only)**: `src/domain/policies.py`'s `expand_query()` + `GLOSSARY` do deterministic corpus-derived acronym expansion (EN expansions are corpus-attested — enforced by test; ES renderings are curated), applied to the **retrieval query only**. `HybridRetriever(expansion_mode=...)` (`"off" | "semantic" | "lexical" | "both"`, default `"off"`) selects which retrieval channel(s) receive the expanded query; `expansion_mode` is not a `Settings` field and is not env-overridable, so production is hard-wired to `"off"`. The original question is always what the answer is generated from.
- **Byte-stable invariants** (never change without an explicit, deliberate decision): refusal cosine threshold `0.5999` and the Phase 3 review floor `0.5500` (both `src/core/config.py`; `0.5500` is pre-registered in ADR-009 — derived from `min(r001, r002)` top1-semantic minus a 0.01 margin, not to be retuned toward individual cases), RRF `k=60` with ties broken by ascending `chunk_id` (`src/domain/policies.py`). All directly unit-tested in `tests/test_domain_policies.py` and `tests/test_core_config.py`. **`0.5500` must never be recalibrated against the 48-question Phase 3 holdout** — the holdout is the measurement set for the pre-registered floor, and tuning the floor to it would destroy the only unbiased evidence the A/B has. A future v2 floor needs its own separate calibration set and a newly frozen holdout. The eval set is now **v1.1.0** (`eval/eval_set.json`); `eval/reports/*_v1.0.0.md` are immutable historical records and must never be regenerated or edited.
- **`raw-v1` / `off` is the canonical historical baseline**, and its frozen artifacts (`eval/reports/*__raw-v1__off.*`, `eval/reports/*_v1.0.0.md`) are never overwritten with `contextual-v1` output. Reports are profile- and mode-labelled in the filename for exactly this reason; a `contextual-v1` measurement goes to a `__contextual-v1__` filename, never on top of a baseline.
- **`chunk_id` is positional**: `src/features/ingestion/cli.py` builds it as `f"{document_id}::chunk-{index:04d}"`, so inserting, deleting, or resizing content anywhere in a corpus document silently renumbers every later chunk in that document — and the frozen eval sets' `expected_chunk_ids` then point at the wrong text while still verifying their own hash. Changing corpus content therefore requires, in order: (1) archive the current `chunks.jsonl` and the frozen datasets, (2) rebuild candidate chunks, (3) **human-review the anchor diff** — which `expected_chunk_ids` moved, and to what — (4) author a new eval-set version rather than editing the frozen one, (5) re-stamp hashes via the `*_integrity --write` commands, (6) re-run `retrieval_eval`. Never silently re-stamp a frozen set to make an integrity check pass.
- **LLM/generation module boundary**: `src/adapters` + `src/features` (FastAPI backend + LLM orchestration) and `src/web` (Streamlit) are separate processes communicating over HTTP only. `src/web/` must never import from `src.domain`, `src.features`, or `src.adapters` directly, even though both live in the same container/repo — this matches the deployed architecture (nginx proxies to two independent processes) and keeps the API genuinely independently testable and reachable. `src/web/i18n.py`'s `UI_LABELS` is a deliberate exception to "don't duplicate": it's a small, documented data duplication of the same catalog concept as `src/features/query/prompts.py`'s `REFUSAL_MESSAGE`/`GENERATION_ERROR_MESSAGE`, kept separate specifically so `src/web/` never needs to import `src.features`.
- Folder layout: `corpus/{public,synthetic}/`, `tests/` (+ `tests/fixtures/mini_corpus/` — a tiny 2-document fixture corpus for CI-safe ingestion/retrieval CLI smoke tests, not the real corpus), `src/core/` (config, errors, logging, paths, telemetry), `src/domain/` (models, policies, ports — framework-free), `src/features/{ingestion,query,retrieval,evaluation}/` (framework-free; `retrieval/chunk_store.py` holds `load_chunks` so serving never imports the index-build CLI), `src/adapters/{primary/http, secondary/{embedder,vector,lexical,llm}}/`, `src/web/` (Streamlit), `src/main.py` (composition root — deliberately lightweight, all adapter construction happens inside FastAPI's `lifespan`, never at import time), `docs/adr/` (8 ADRs), `docs/architecture/` (C4 mermaid diagrams). `ingestion/output/`, `retrieval/output/`, `eval/eval_set.json`, `eval/reports/` remain as data/build-artifact directories, not code. Don't invent new top-level folders without a reason tied to a specific phase's scope.

## CFR Numbering → Markdown Heading Convention

Federal regulation text (21 CFR Part 211, 29 CFR 1910.1200) is numbered (`§ 211.22`, paragraph `(a)`, sub-paragraph `(1)`), not naturally headed the way an SOP or manual is. When converting CFR text to the corpus Markdown format, each numbered level maps one-to-one to a Markdown heading level:

- `##` — a Subpart (e.g. `## Subpart B—Organization and Personnel`) or, where a section stands with its own numbered paragraphs, the section itself (e.g. `## (a) Purpose`).
- `###` — an individual section (`### § 211.22 Responsibilities of quality control unit`) or a lettered paragraph under a section-level `##`.
- `####` — a numbered sub-paragraph, if it's substantial enough to need its own heading (short numbered items are usually left as plain list items within their parent heading instead — use judgment; the goal is a `section_heading` breadcrumb from the chunker that's still a useful citation, not a heading for every single `(a)(1)(i)`).

Apply this convention consistently if more regulatory text is added to the corpus later — don't invent a different scheme per document.

## Prohibited Patterns

- **No hardcoded API keys.** `.env.example` is tracked with empty placeholder keys; the real `.env` is gitignored.
- **No chunk emitted with incomplete metadata.** Every chunk must have a non-empty `document_id`, `document_title`, `section_heading`, `source_type`, `source_url_or_note`, `chunk_id`, and `md_line_range`. `source_page_range` is the one documented exception — `null` is valid and expected for every synthetic document (see `src/domain/models.py`'s `ChunkMetadata`). If a required field would be empty, the pipeline must raise, not silently drop or default it — this mirrors the citation-mandatory, no-silent-fallback-to-hallucination standard the whole project is built around.
- **No copyrighted PDFs committed to this repo**, ever. See `SPEC.md`'s Data-Honesty Policy.
- **No new corpus file without a matching `corpus/SOURCES.md` row.** `tests/test_ingestion_use_cases.py` enforces this — don't skip it or mark it `xfail` to get a file in.
- **No silent fallback that could look like hallucination-adjacent behavior** — don't build patterns (e.g. defaulting a missing field to `"unknown"` instead of raising) that could mask a real gap.
- **No partial citation resolution.** A citation set is all-or-nothing (see the citation-integrity entry above). Re-introducing "drop the bad one, serve the rest" would let a partly-unverifiable answer be presented as fully cited.
- **No corpus content change without re-anchoring the frozen eval sets.** `chunk_id` is positional; see the Conventions entry above for the required procedure.
- **No recalibration of `REFUSAL_REVIEW_FLOOR` against the Phase 3 holdout.**
- **No citation field trusted from LLM output beyond `chunk_id`.** `src/domain/policies.py`'s `CitationResolver` always looks up `document_id`/`document_title`/`section_heading`/`revision` from the real retrieved chunk's metadata, never from the LLM's own JSON output — this is what prevents citation hallucination; a change that starts trusting LLM-supplied citation text for these fields would reintroduce exactly the failure mode this project is built to avoid.
- **No `pickle.load`/`pickle.dump` in this project's own runtime code.** `src/adapters/secondary/lexical/bm25_lexical_index.py` persists the BM25 index as JSON (tokenized corpus, rebuilt in memory on load) specifically to avoid this — see `docs/adr/004-bm25-json-persistence.md`.
- **No new module-level mutable singleton** (the pre-refactor code's `_model`/`_CACHE`/`_encoding` globals were eliminated during the `src/` migration — don't reintroduce the pattern; adapter/composition-root-managed instance state is the replacement).

## Scope Discipline

This is a phased project — see `SPEC.md` for what's in scope per phase, and the migration ADRs for the `src/` refactor's own phase boundaries. Phase 4b (deleting `start.sh`/`nginx.conf`, splitting into separate `api`+`web` Docker containers) is explicitly deferred — see `docs/adr/005-deploy-container-shape.md` — do not implement it without a separate, explicit decision on the replacement deploy target.
